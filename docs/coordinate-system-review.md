## 必须分开的概念

| 概念 | 意义 | 对写字机的影响 |
| --- | --- | --- |
| 机器坐标 MPos | 控制器记录的机床位置，通常通过正确回零建立参考 | 不应被“纸张置零”修改 |
| 工件坐标 WPos | 当前所选工件坐标系下的位置 | 可以作为纸张的书写坐标 |
| 工件坐标系 G54–G59 | GRBL 支持的六套工作偏移 | 可用于不同纸张位置或夹具，但必须读取当前实际状态 |
| WCO | 当前总工作偏移 | 不能只当成 G54 的三个值，还可能包含 G92 和刀长补偿 |
| G90 / G91 | 绝对 / 相对运动模式 | 不等于机器 / 工件坐标选择 |
| G53 | 单条运动命令使用机器坐标 | 不是像 G54 一样持续生效的下拉选项 |
| 纸张显示原点 | 页面排版与图形变换 | 切换显示角落不能悄悄修改控制器偏移或反转电机方向 |

GRBL 官方关系：`WPos = MPos - WCO`，反向为 `MPos = WPos + WCO`。

GRBL v1.1 通常只报告 MPos 或 WPos 其中之一，WCO 间歇出现。只有取得可信的 WCO 后才推导另一个坐标；重连、复位后不得沿用旧连接的缓存。

注意：这些是**控制器报告的位置**。没有编码器反馈时，不应称为“电机实测位置”；更不能用已发送或已应答的指令目标冒充当前坐标。

## 读取与切换的协议依据

- `?`：读取运动状态与位置报告。
- `$G`：读取当前模态，包含 G54–G59、G20/G21、G90/G91 等。
- `$#`：读取工件偏移、G92、TLO 等参数。
- `$$`：读取设置。需要识别 `$13` 报告单位及有关回零 / 行程的配置；**G21 不代表位置报告一定以毫米输出**。
- `G54`–`G59`：切换活动工件坐标系。必须等待应答并重新查询状态，不能只在浏览器里换一个标签。
- `G10 L20 P1 X0 Y0`：以当前物理位置设置 G54 的 X/Y 工件读数为零。P1–P6 对应 G54–G59。应根据实际活动坐标系决定 P 值，不应硬编码为 P1。
- `G92`：临时坐标偏移。GRBL 文档说明其不在复位或断电后保留，不建议作为本项目默认纸张标定方式。
- `$H`：GRBL 回零；需要固件、限位开关和机械结构支持。**不能把 G28 当作 GRBL 回零**，G28 可移动到存储的位置。
- GRBL v1.1 点动优先考虑专用 `$J=`，明确距离、单位与进给，配合实时取消；不要让点动改变任务 G90/G91 模态。

CNCjs 针对不同控制器使用不同能力表。其 Marlin 路径与 GRBL 路径并不通用；不能仅凭“奎享”或“USB”判定应发哪套命令。

## 本项目建议的最小界面

不照搬整套 CNC 操作面板，只保留写字机需要的项目：

1. 坐标读数：机器 / 工件显示切换，XYZ，报告来源和过期状态。未连接或字段未知显示 `—`，不默认填零。
2. 当前工作坐标系：显示从控制器读到的 G54–G59；仅在确认能力、空闲、状态新鲜时允许切换。
3. 纸张定位：X、Y 单轴 / 联合设零。Z 另行标定，不把当前抬笔高度默认设成纸面零点。
4. 点动：有限步长、方向和速度；设备不具备某轴时不展示该轴的运动操作。
5. 回零与返回纸张原点分开。返回纸张原点前必须根据已验证的抬笔方式和安全高度制定顺序，不直接发送 XYZ 同时归零运动。

所有实际写入 / 运动操作需要真实后端支持，不能先放没有功能的按钮。协议未确认时，只保留可用功能与明确状态。

## 调研时的真实缺口（历史基线）

以下描述实施前的状态，不代表当前版本仍全部缺失：

- `server.py` 的 HTTP status 是桥接任务状态，不是完整 GRBL 位置 / 模态状态；空闲时尚无持续的位置采集。
- 串口读取主要在任务线程中进行。扩展坐标查询前需要一个统一读循环和指令调度，避免任务应答与状态查询互相抢读。
- 没有 `$G`、`$#`、`$$` 的完整查询、解析和读回验证。
- 硬件发送白名单故意不接受 G54–G59、G10、G53、G92、回零与点动。开放它们必须新增独立的受控接口，不是放宽任意 G-code 透传。
- 当前 XYZ 范围只验证用户填写的工作坐标数字，不能替代在 WCO 转换后进行的机器坐标行程校验。GRBL 机器坐标也可能是负数，不能强制假设机器范围始终为 0 到纸张尺寸。
- 当前生成器未绑定具体活动工件坐标系；发送前需要验证活动 WCS / WCO，并把任务固定到已确认的坐标状态，禁止运行中切换。
- 刀轨预览初始点是预览约定的零点，不是从机器读取的位置。第一段空移与真实位置的关联需要采集状态后单独处理。

## 建议实施顺序与验收

1. **只读采集**：单一串口读循环；解析状态、单位、模态和偏移。测试字段缺失、WCO 间歇上报、断线、复位、英寸报告、报警和陈旧数据。
2. **工件坐标设置**：仅在空闲时处理所支持的 G54–G59 与 X/Y 置零，等待应答后查询验证，并清除旧的任务安全确认。
3. **点动与回零**：先确认奎享控制板、固件、轴定义、限位与抬笔方式，再针对实际能力实现取消、限位和安全路径。
4. **任务约束**：固定 WCS、校验 WCO 和数据新鲜度，同时检查纸张范围与变换后的机器行程。运行中锁定会影响坐标的操作。

下一步硬件信息：奎享具体型号、配套软件 / 控制板资料、固件版本、是否带限位、Z 是电机轴还是舵机抬笔。不能用开源项目的指令集替代这些确认。

## 当前首阶段实现

- `grbl.py`：单一 USB 读循环，分片拼接、实时状态与指令应答分流；命令串行调度，查询 / 坐标操作 / 任务互斥。应答超时后隔离后续普通命令，不让迟到 `ok` 错配。
- 仅标准 GRBL 1.1 三轴报告；通过 `?`、`$$`、`$G`、`$#` 获取真实状态。根据 `$13` 换算报告毫米，识别间歇 WCO，校验活动 WCS 偏移 + G92 + TLO 与 WCO 一致。复位、报警、断线清除可信状态；2.5 秒位置过期、10 秒模态过期均禁用新写入。
- `coordinates.js` / `coordinates.css`：直角主题坐标面板，机器 / 工件显示切换不写设备；未连接、缺失、过期显示 `—`。G54–G59、X/Y/XY 设零各有受控接口、内置确认、前后令牌检查与读回验证；不修改 Z，不承诺设备回零。
- `server.py`：任务重新查询并检查 Idle / 坐标与位置令牌；固定 G21/G90/G17/G94/初始 G0 模态和所选 WCS，首个 G1 运动要求显式 F。源程序白名单不开放 G10/G54/G53 等任意坐标指令。按实际起点和 WCO 验证转换后的机器行程，独立验证纸张范围；机器坐标允许负数，范围由用户核对填写，不从行程长度猜测。
- 任务期间监测基准与状态新鲜度，异常停止追加并尝试 Feed Hold；暂停时故障也会释放任务锁。软复位后坐标失效，必须检查后重新连接。
- Python 协议 / HTTP 模拟测试与桌面 / 手机浏览器 API 模拟回归覆盖已实现流程；未向实际 USB 设备执行验收指令。
